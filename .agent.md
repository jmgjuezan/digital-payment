# Global Project Context & Standards

This full-stack application utilizes **Next.js (App Router)**, **Prisma ORM** for database access, **Supabase Auth UI** for user management, **TypeScript**, **Tailwind CSS**, and **shadcn/ui**, deployed globally via **Vercel**. AI operations must tightly enforce serverless optimization, secure environment configuration, and strict separation of concerns.

## 🚀 Vercel Deployment & Serverless Optimization
- **Connection Pooling:** Because Vercel utilizes ephemeral serverless functions, direct PostgreSQL connections will exhaust database limits. Always use a connection-pooled connection string (`DATABASE_URL`) for runtime queries and a direct string (`DIRECT_URL`) strictly for Prisma migrations.
- **Runtime Specification:** Prefer the default Serverless Node.js runtime unless a route strictly benefits from the Edge Runtime (e.g., global Middleware or geolocation-dependent APIs). Do not blindly mark paths with `export const runtime = 'edge'` if they use Prisma libraries that are incompatible with edge environments.
- **Environment Variables:** Never hardcode secrets. Always read from `process.env`. All required environment variables (e.g., `NEXT_PUBLIC_SUPABASE_URL`, `DATABASE_URL`) must follow Vercel's production vs. preview system patterns.

## 🔑 Authentication (Supabase Auth UI)
- **Client Auth:** Use `@supabase/auth-ui-react` and `@supabase/auth-ui-shared` for login and registration forms. 
- **Styling Injection:** Always inject Tailwind CSS classes into the Auth UI components via the `appearance={{ theme: ThemeSupa }}` config or custom Tailwind class overrides.
- **Vercel Deployment URL Safety:** When configuring redirect URLs for authentication, dynamically resolve the application root using Vercel environment parameters (`process.env.NEXT_PUBLIC_VERCEL_URL`) to allow seamless authentication flow testing on Preview deployments.

## 💾 Database & Data Modeling (Prisma ORM)
- **Separation of Concerns:** Use **Supabase** solely for Authentication, JWT generation, and User Metadata. Use **Prisma Client** for all database queries and business logic.
- **Prisma Client Instance:** Prevent connection pooling exhaustion in development and serverless environments. Always use a global singleton pattern (`globalThis.prisma`) for instantiating `PrismaClient`.
- **Server Execution Only:** Prisma queries must *never* be imported or executed inside Client Components (`'use client'`). Execute them inside React Server Components or React Server Actions (`'use server'`).

## 🏢 Next.js App Router & Server Actions
- **RSC First:** Treat all `app/` folder files as Server Components by default. Fetch data via Prisma directly inside these async components.
- **Server Actions:** Use `'use server'` actions for any form submissions or Prisma mutations. Wrap mutations in `try/catch` and return structured JSON types `{ success: boolean, error?: string, data?: T }`.
- **Cache Invalidation:** Call `revalidatePath` or `revalidateTag` immediately following a Prisma mutation to ensure Vercel's Data Cache and Edge Network are completely synchronized.

## 💻 UI & Styling (Tailwind CSS)
- Enforce strict Tailwind CSS utility classes using a mobile-first philosophy (`sm:`, `md:`, `lg:`).
- Maintain absolute TypeScript safety. Never accept `any`. Explicitly type all Prisma query results using Prisma's generated types.
