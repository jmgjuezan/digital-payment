Migration `20261102000000_use_email_for_payment_creator.sql` replaces existing creator UUIDs with the corresponding `user_roles.email`. It stops with an error if any existing payment creator has no matching non-empty email, so those role records must be corrected before applying it. Migration `20261104000000_generate_payment_creator_in_database.sql` sets `created_by` before each insert; application inserts should omit `id`, `created_at`, and `created_by`.

Migration `20261103000000_admin_moderator_update_payments.sql` grants payment update access only to authenticated users with the `admin` or `moderator` role.

## Table `user_roles`

### Custom user roles

Users can have one of three custom roles: `admin`, `moderator`, or `user`. The role and email are stored in `user_roles` and associated with a Supabase Auth user through `user_id`. A database trigger uses this row's email for `payments.created_by`.
